# Бот объявлений об аренде

Локальная версия по требованиям из переписки 6–7 октября 2026 года.
Python 3.10+, aiogram 3, SQLite. Цена по указанию заказчика разработки: **400 сомов на 7 дней**.

## Что сделано

- Каталог квартир в Telegram-канале. Администратор вручную добавляет 1–10 фото, описание и отдельный телефон хозяина.
- Под объявлением: **Получить номер**, **Ищу квартиру**, **Техподдержка**. Проверка актуальности не включена.
- Контакт хозяина выдаётся только в личном чате и только при действующей подписке. В публичную карточку контактное поле не подставляется; телефоноподобные последовательности в описании блокируются.
- Оплата по вашим реквизитам и, при настройке, QR. Пользователь присылает фото/PDF чека.
- Отдельный админ-чат получает чек, username/имя и Telegram ID пользователя, сумму и кнопки «Принять»/«Отклонить». Решение разрешено только ID из ADMIN_IDS и только в ADMIN_CHAT_ID.
- Принятый чек открывает доступ на 7 дней; повторное нажатие не продлевает подписку повторно. Новый платёж продлевает от более поздней даты: сейчас или конец текущего доступа.
- «Ищу квартиру»: комнаты, район, телефон, предпросмотр с предупреждением о публичности контакта. Публикация за 10 подтверждённых приглашений.
- Диалоги, черновики, подписки, чеки, приглашения и история публикаций сохраняются в SQLite.
- Повторная публикация завершённой карточки не создаёт копию. Подтверждённые шаги публикации сохраняются; неопределённый сетевой результат требует проверки администратором.

Объявления, переводы и чеки обрабатываются вручную. Бот не интегрируется с существующим сайтом и не подтверждает реальное поступление денег сам.

## Что ещё нужно для живого запуска

Нужны собственный бот, его токен BotFather, канал каталога, чат проверки чеков, ID администраторов, настоящие реквизиты/QR и контакт поддержки.
В этой поставке нет токенов и нет подключения к реальному боту. Локальные тесты используют подменённый Telegram-транспорт.

## Основной запуск: Docker в Windows

Папка проекта: `C:\Users\dasmu\projects\rentbot`.
Файл `.env` уже создан рядом с `compose.yaml`; заполните его настоящими значениями.
Цена по умолчанию — **400 сомов / 7 дней**.

Для запуска нужен настроенный Docker Engine и плагин Compose в используемом терминале.
На этом компьютере 8 октября 2026 установлен Docker Engine 29.8.2 и Compose 5.6.0
в Ubuntu-24.04 WSL. Из PowerShell команды передаются в WSL через `docker.cmd`.
Docker Desktop не требуется и не установлен.
Прямая команда из `C:\Users\dasmu\projects>`:

```powershell
docker compose -f ./rentbot/compose.yaml up -d --build
```

Если терминал уже открыт в `C:\Users\dasmu\projects\rentbot`, команда короче:

```powershell
docker compose up -d --build
```

Ошибка «docker не распознано» означает, что Docker CLI недоступен в этом терминале.
На этом компьютере команда добавлена в пользовательский PATH. Для её использования
откройте новый PowerShell из меню «Пуск». В уже открытом терминале внутри папки проекта
можно сразу использовать `.\docker.cmd compose up -d --build` или `.\start.cmd`.
В аргументах передаваемых в WSL команд используйте пути с `/`, например `./compose.yaml`;
абсолютные пути к диску C имеют вид `/mnt/c/...`.

Вариант с предварительной проверкой `.env` из того же PowerShell:

```powershell
.\rentbot\start.cmd
```

Скрипт использует уже настроенный Docker Engine с Compose, собирает образ,
проверяет формат `.env` внутри контейнера и поднимает бот в фоне.
Сам скрипт ничего не устанавливает и не меняет автозагрузку Windows.
Локальный `docker.cmd` запускает фоновый помощник WSL, чтобы движок продолжал работать
после закрытия терминала. Повторный вызов не создаёт второй постоянный помощник.
Если настройки не заполнены, постоянный контейнер не запускается.
При старте самого бота проверяются токен, username, доступность чатов и права в канале.
Чтобы проверить результат этих сетевых проверок, откройте логи.

Повторяйте **ту же команду после изменения `.env` или кода**: Compose применит изменения.
Не используйте для применения `.env` только `docker compose restart`.
Python и виртуальное окружение на Windows для Docker-запуска не нужны.
`start.cmd` запускает локальный `start.ps1`; системную политику исполнения PowerShell не меняет.

```powershell
# Из C:\Users\dasmu\projects:
.\rentbot\start.cmd -Mode check   # Сборка и проверка формата .env без Telegram
.\rentbot\start.cmd -Mode status  # Состояние контейнера
.\rentbot\start.cmd -Mode logs    # Логи; Ctrl+C закрывает просмотр, бот продолжает работать
.\rentbot\start.cmd -Mode stop    # Остановить бот и сохранить базу
.\rentbot\start.cmd -Mode ids     # Помощник /myid; нужен только BOT_TOKEN
```

Режим `ids` сначала останавливает основной контейнер, чтобы не запустить два polling-процесса.
После получения ID нажмите Ctrl+C, дополните `.env` и выполните обычный запуск.
Добавьте бота администратором канала с правом публикации и администратором REQUIRED_CHAT_ID.

### Автоподнятие и данные

В Compose настроено `restart: unless-stopped`: после выхода процесса и перезапуска Docker
ранее запущенный бот поднимется автоматически. После ручной команды `stop` он останется
остановленным до обычного запуска. После перезагрузки хоста должен запуститься сам
Docker Engine: его автозапуск настраивается в окружении, где он установлен.
На этом компьютере службы `docker` и `containerd` включены в systemd. Задача Windows
`RentbotDockerEngine` запускается при входе пользователя и удерживает WSL активным
независимо от открытого терминала. Она работает в фоне через `wsl-host.ps1`.
`wsl-keepalive.ps1` проверяет задачу и запускает её, если она остановлена.
Автозапуск до входа пользователя в Windows не настраивался.
При выключенном компьютере или во время сна бот не обслуживает запросы.

База SQLite хранится в постоянном Docker-томе **`rentbot_bot-data`** по пути
`/app/data/rentbot.sqlite3`. Пересборка и пересоздание контейнера не удаляют данные.
В Docker значение DB_PATH закреплено в Compose; локальная папка `data` используется только
для запуска через Python. Стабильное имя проекта `rentbot` сохраняет имя тома при переносе папки.
Не используйте `docker compose down -v`: эта команда удаляет базу вместе с томом.
Логи ограничены тремя файлами по 10 МБ. Контейнер работает от непривилегированного пользователя.

Из самой папки проекта можно использовать обычные команды Docker:

```powershell
docker compose up -d --build
docker compose logs -f bot
docker compose stop
```

Прямая команда `up` не выполняет отдельную предварительную проверку настроек, поэтому для
первого запуска удобнее `start.cmd`. Все настройки и `.env` находятся в папке проекта;
секреты не копируются в образ и исключены из Git.

## Дополнительный запуск через Python в Windows

1. Откройте PowerShell в папке проекта. Если `.env` отсутствует, скопируйте шаблон:
   `Copy-Item .env.example .env`. Существующий заполненный файл не заменяйте.
2. Заполните значения в `.env`. Токен храните только локально, не отправляйте файл клиентам и не добавляйте в Git.
3. Для получения своего ID и ID админ-группы после заполнения только BOT_TOKEN:
   `.\run.ps1 -Mode ids`.
   Отправьте `/myid` боту лично и в нужной группе; остановите помощник Ctrl+C.
4. Добавьте бота администратором канала с правом публикации. Для проверки вступления он также должен быть администратором REQUIRED_CHAT_ID.
5. Заполните оставшиеся значения и проверьте синтаксис:
   `.\run.ps1 -Mode check`.
6. Запустите:
   `.\run.ps1 -Mode run`.

Скрипт создаёт `.venv` внутри проекта. Если Python не найден, передайте
`-PythonExe C:\Path\python.exe`. Можно выполнять команды вручную:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m rentbot check
.\.venv\Scripts\python.exe -m rentbot run
```

`check` проверяет только заполненность и формат конфигурации, без сетевого подключения.
При `run` проверяются токен, username, доступность целевых чатов и права бота в канале.
Для получения CHANNEL_ID публичного канала: `.\.venv\Scripts\python.exe -m rentbot ids --chat @имя_канала` (нужен только BOT_TOKEN). Для приватного канала добавьте бота администратором, запустите режим `ids` и опубликуйте команду `/myid` в канале. Не отправляйте токен сторонним сервисам.

## Настройки

| Переменная | Назначение |
|---|---|
| BOT_TOKEN | Токен вашего бота |
| BOT_USERNAME | Можно оставить пустым: реальное имя берётся при запуске |
| ADMIN_IDS | Положительные числовые ID людей через запятую |
| ADMIN_CHAT_ID | Числовой ID чата ручной проверки чеков |
| CHANNEL_ID / CHANNEL_URL | Числовой ID и ссылка на каталог |
| REQUEST_CHAT_ID | Куда публиковать заявки; по умолчанию CHANNEL_ID |
| REQUIRED_CHAT_ID | Чат, вступление в который подтверждает приглашение; по умолчанию CHANNEL_ID |
| REQUIRED_CHAT_URL | Ссылка на этот чат; по умолчанию CHANNEL_URL |
| SUPPORT_URL | Ссылка https://t.me/... на поддержку |
| SUBSCRIPTION_PRICE | По умолчанию 400 сомов |
| SUBSCRIPTION_DAYS | По умолчанию 7 суток с момента подтверждения |
| REFERRAL_GOAL | По умолчанию 10 приглашений на одну заявку |
| PAYMENT_DETAILS | Настоящие реквизиты; последовательность `\n` даёт перенос |
| PAYMENT_QR_FILE_ID | Необязательный file_id фотографии QR |
| DB_PATH | По умолчанию data/rentbot.sqlite3 |

Для QR отправьте боту фото, затем ответьте на него `/fileid` от администратора.
Поместите полученный ID в PAYMENT_QR_FILE_ID и перезапустите бот.

## Повседневная работа

Администратор в личном чате:
- `/admin` — памятка.
- `/newlisting` — фото → «Готово» → описание → телефон → предпросмотр → публикация.
- `/listings` — список объявлений с управлением; `/listing ID` — конкретное объявление.
- `/payments` — повторная доставка ожидающих чеков в чат проверки.
- `/fileid` — ID фото, на которое отвечает команда.
- `/cancel` — отмена текущего ввода.

Пользователь:
- `/start`, `/help` — каталог и меню.
- `/subscribe` — реквизиты и отправка чека.
- `/receiptstatus` — статус своего последнего чека и повтор доставки при необходимости.
- `/cancel` — отмена ввода.

Отключение объявления прекращает выдачу номера, но не удаляет опубликованный пост.
Фотографии публикуются альбомом, затем отдельной текстовой карточкой с кнопками:
официальный sendMediaGroup не принимает reply_markup.

## Приглашения: выбранная трактовка

Личная ссылка имеет вид `https://t.me/ИМЯ_БОТА?start=ref_ID`.
Засчитывается только ранее неизвестный боту пользователь, который впервые пришёл по этой ссылке,
вступил в настроенный чат и нажал «Проверить приглашение». Повторный вход, самоприглашение
и изменение пригласившего не начисляют новые приглашения. Ошибка проверки Telegram не считается вступлением.

**10 приглашений расходуются на одну заявку.** Это рабочее допущение: в переписке не уточнено,
должны ли десять приглашений открывать бессрочную возможность публиковать заявки. Число настраивается.
Засчитанные приглашения не отзываются при последующем выходе приглашённого.
Защита от нескольких аккаунтов одного человека не реализована; для неё нужны дополнительные продуктовые правила.

Публикация заявки требует явного подтверждения предпросмотра, где видны район и публикуемый телефон.
Если отправка не удалась, зарезервированная заявка и её оплаченные приглашениями данные восстанавливаются,
а повторная попытка не списывает приглашения ещё раз.

## Сбои и восстановление

Для одного бота запускайте **один polling-процесс**. Не запускайте одновременно Windows-экземпляр и Docker.

- Чек сохранён, но сообщение администраторам не доставлено: пользователь `/receiptstatus` или администратор `/payments`.
- Подтверждение сохранено, но личное уведомление не доставлено: пользователь повторно открывает «Получить номер»; доступ уже сохранён.
- Telegram явно отклонил публикацию: исправьте права/данные и повторите публикацию.
- Таймаут после отправки: нельзя достоверно узнать, появился ли пост. Бот останавливает повтор, чтобы не дублировать его.

После проверки канала оператор использует:

```powershell
.\.venv\Scripts\python.exe -m rentbot deliveries
# Карточка объявления действительно появилась с указанным message_id:
.\.venv\Scripts\python.exe -m rentbot reconcile listing 12 --message-id 345
# Или спорный шаг точно НЕ появился, разрешить повтор:
.\.venv\Scripts\python.exe -m rentbot reconcile listing 12 --retry
# Аналогично для заявки:
.\.venv\Scripts\python.exe -m rentbot reconcile request 8 --message-id 456
```

После `--retry` повторите публикацию в боте. Если неоднозначной была отправка альбома и он всё-таки появился,
сначала вручную решите, сохранять ли его или удалить, затем разрешайте повтор. CLI не удаляет сообщения.

Остановите бот перед ручными операциями восстановления и резервным копированием.
При локальном запуске сохраняйте папку data; при Docker-запуске — содержимое тома
rentbot_bot-data (SQLite содержит контакты, данные пользователей и ссылки на чеки).
Для резервной копии на работающем экземпляре используйте SQLite backup API, а не копирование одного .sqlite3 без WAL.

## Границы реализации и проверки

- Показ номера возможен после первого открытия личного чата с ботом. Telegram может показать кнопку Start:
  обещать её отсутствие для нового пользователя нельзя.
- Номера в текстах блокируются, **изображения не проходят OCR**. Администратор должен выбирать фото без водяных знаков с контактами.
- Повтор одного Telegram file_id чека блокируется. Повторно загруженный файл с новым file_id распознаётся только при ручной проверке перевода.
- Поддержка добавлена как кнопка из присланного образца; последние слова голосового о ней распознаны неоднозначно.
- Точный банк/QR, каналы и сервер в переписке не заданы и заполняются при запуске.
- Итоги реальной проверки Docker на этом компьютере записаны в VALIDATION.txt.
